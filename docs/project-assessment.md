## 四、主要问题清单与根因

| # | 问题 | 严重度 | 根因 |
|---|---|---|---|
| P1 | 前端技术栈偏差（React+Vite+Tailwind → 原生 HTML/JS/CSS） | 高 | 为"单机零构建"的务实决策，但**未同步更新文档**，导致规格与实现不一致 |
| P2 | `insight_notes` 表缺失，心得未落库 | 中 | 开发时简化，忽略了需求数据模型中的独立实体 |
| P3 | 语音可插拔抽象（ASR/TTS Provider）未实现 | 中 | MVP 直接用浏览器能力，未预留后端抽象层 |
| P4 | `main.py` 单文件 573 行、路由未拆分 | 中 | 快速迭代优先，技术债累积 |
| P5 | 测试覆盖不足（无错误路径、无前端交互测试） | 中 | 时间压力，仅覆盖核心链路 |
| P6 | 错误处理不完整（无 LLM 重试、无权限引导、无补录界面） | 中 | 需求 12 节边界情况未逐条落地 |
| P7 | 小鸭档案 summary 未注入对话 | 低 | 对话引擎只取 status，未 join archive |
| P8 | 无日志/监控 | 低 | 个人工具定位，暂未做 |
| P9 | WebSocket 未用（架构图提到） | 低 | 实际 HTTP 轮询/请求即可满足，架构图超前 |
| P10 | README 严重过时 + 遗留文件混乱 | 中 | README 仍是" CrewAI 模板"描述（标题/目录结构/快速开始都未反映鸭鸭日记本应用）；根目录遗留 `overview.md`（早期模板总结）、`prototype/duck-diary-core-interaction.html`（早期原型）、`scripts/test_connection.py`（早期连接测试），与现状脱节，新接手者会被误导 |

**根因归纳**：① 需求理解与实现的"务实简化"未被显式记录，形成规格-实现偏差；② 快速迭代带来技术债（单文件、dict payload）；③ 测试与文档作为"最后一步"被压缩；④ **文档未随迭代同步更新**（README 停留在项目最初的 CrewAI 模板阶段，功能演进后未回填）。

## 五、改进路线图

### A. 短期快速修复（1-2 天内，低风险高收益）

| 优先级 | 任务 | 收益 |

| B6 | 引入日志（logging）+ 简单 usage 监控 | 可观测性 |

### C. 长期（按需）

| 优先级 | 任务 | 说明 |

## 六、结论

项目已从"想法"推进到"可运行、可验收的 MVP"：核心业务闭环完整、AI 引擎健壮、IP 形象已集成、CrewAI 团队与 e2e 验证齐全。但离"完备交付"存在明确差距——**功能细节（insight/请假补位/对比/语音抽象）、代码结构（单文件/未分层）、测试与文档一致性**是三大短板。

建议按 **A（快速修复）→ B（中期重构）** 顺序推进，优先解决规格-实现偏差与数据缺口（A1/A2/A6），再逐步偿还技术债。
