# 幼儿端交互流与语音体验优化 — 设计规格

- 日期：2026-08-22
- 背景：人工验收发现幼儿端 3 个体验问题，已与主人讨论定案

---

## 一、值日生选择（问题 1）—— 方案 C

**现状**：幼儿端 `renderPicker` 拉取全部幼儿（`/api/children`），与"每日 2 名值日生轮值"的需求不符。

**方案**：
- 后端新增 `GET /api/roster/today`：返回 `date=今天` 的排班对应幼儿列表（含 id/name/nickname）。
- 前端 `renderPicker` 先请求 `/api/roster/today`：
  - 有值日生 → 只展示当天值日生（通常 2 名）；
  - 无排班（周末/漏排）→ 降级展示全部幼儿。

## 二、开场页优化（问题 2）—— 方案 B + CSS 动效

**现状**：选人 → 静态开场页（含"开始说话"按钮）→ 点击进入对话，两步冗余且静态图体验差。

**方案**：
- **去按钮、自动进入**：开场页保留仪式感，语音播报完毕后**自动进入对话**（不再需要点击"开始说话"）。
- **CSS 动效增强**（零素材成本，复用现有 3 表情 PNG）：
  - 表情切换：happy（出场）→ front（停留）→ listening（进入对话）
  - 上下浮动 + 轻微摇摆 + 影子呼吸 + 星星/爱心粒子
- **随机开场语**：准备 2-3 句开场白，随机抽取（含各自小名）。

## 三、语音预加载 + 锁死（问题 3）

**现状**：Edge-TTS 每次现合成（实测 6.97s），连续点击导致语音被 cancel 漏播；对话回复期间未锁死 PTT。

**方案**：
1. **后端 TTS 缓存**：`/api/tts` 按文本哈希缓存 mp3 到 `data/tts_cache/`，相同文本不重复合成。
2. **前端预加载**：
   - 固定引导语（选人引导、结束语）进入页面前预合成；
   - **当天值日生完整开场语**（"你好呀小明！…"含小名）在进入选人页时预合成 2 名，点谁秒播（解决"称呼+固定语"无法模板化的问题）。
3. **对话回复锁死 PTT**：LLM 回复期间 PTT 置灰 + 显示"鸭鸭在想…"，回复**播报完毕**后解锁（符合阻塞式多轮架构，顺带修复并发请求隐患）。

---

## 验收标准

1. 幼儿端只显示当天值日生（无排班时降级全部）。
2. 点名字 → 开场动画 + 语音 → 自动进对话，无多余点击。
3. 选人/开场/结束语音秒播（预加载），对话回复期间 PTT 锁定、播完解锁。
4. 全程统一 Edge-TTS 晓晓音色。

## 不做（YAGNI）

- 不做幼儿端全量搜索/翻页（值日生仅 2 人）。
- 不做 gif/Lottie 动画素材（CSS 动效先行，后续可替换）。
- 不做播放队列（阻塞式锁死已避免堆积）。
