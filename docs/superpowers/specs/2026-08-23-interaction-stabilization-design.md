# 鸭鸭日记本：48 小时交互止血与分阶段优化设计

- 日期：2026-08-23
- 状态：设计已在对话中逐节确认，等待书面规格复核
- 类型：架构级交互改造
- 目标：先恢复数据、状态与反馈的可信度，再以脱敏 Lovable 原型驱动后续界面优化

## 1. 背景与结论

当前项目已经交付，但运行态存在前后端版本不一致、活动进程绑定旧数据库、测试直接重建应用数据库、错误被伪装成成功、教师审阅修改静默丢失、会话不可恢复以及关键控件不可键盘操作等问题。

本轮不把问题定义为“视觉风格不足”，而是定义为“核心任务闭环不可信”。在以下止血门槛全部通过前，项目保持 **NO-GO**，不得继续按可验收版本演示。

## 2. 已确认的产品约束

1. 当前数据全部为演示或测试数据，允许重建，不做旧数据迁移。
2. 幼儿端与教师端在同一台电脑使用，服务仅监听 `127.0.0.1`。
3. 教师端使用 4–6 位 PIN 解锁。
4. PIN 输入成功后保持浏览器会话解锁，关闭浏览器后失效；不做闲置超时，同时提供“立即锁定”。
5. 幼儿通过点击主按钮开始说话，停顿后自动结束并发送；空格键提供同等操作。
6. 幼儿端提供“老师帮忙”入口。解锁后可文字补录、重试麦克风、保存草稿或结束会话。
7. 教师首页采用“今日任务工作台”，优先展示今日排班、开始对话和待审阅队列。
8. 教师审阅采用“左侧待审阅队列 + 右侧双栏审阅”，同时展示原始对话和结构化结果。
9. Lovable 仅使用虚构数据制作高保真原型；48 小时止血期不引入 React 全量迁移。

## 3. 目标与非目标

### 3.1 目标

- 任何失败都不能显示为成功。
- 任何重复点击、重试或刷新都不能制造重复会话、重复排班或重复评估。
- 幼儿说过但未成功提交的内容必须保留并可重试。
- 教师修改的流水、情绪、心得、分数和理由必须原子保存。
- 应用数据库和测试数据库必须物理隔离，测试不得触碰应用数据。
- 前后端加载版本不一致时必须阻止进入业务页面。
- 核心流程支持鼠标、触摸和键盘，并提供明确焦点与状态播报。
- 48 小时内交付可验证的止血版本和独立的脱敏 Lovable 原型。

### 3.2 非目标

- 不迁移或保留当前演示数据库中的旧记录。
- 不做公网访问、多园区、多班级或多教师账号体系。
- 不在本轮将原生 HTML/CSS/JS 全量迁移为 React。
- 不在止血期重做全部视觉资产、动画或成长分析功能。
- 不把 Lovable 生成代码直接接入应用数据库或生产 API。

## 4. 总体架构

系统按三层边界整理：

1. **浏览器交互层**
   - 幼儿端显式状态机。
   - 教师今日任务工作台。
   - 教师双栏审阅工作台。
   - 统一 API 客户端、错误呈现与会话恢复。
2. **可信 API 层**
   - API 状态检查、超时和标准错误结构。
   - 请求幂等、版本握手、教师会话校验。
   - 会话保存与分析任务解耦。
   - 审阅原子提交和排班唯一性保证。
3. **数据与服务层**
   - 应用数据库、测试数据库和 TTS 缓存分别存放。
   - 持久化分析任务状态，服务重启后可恢复。
   - 健康检查报告加载版本、数据库模式和 schema 版本。

## 5. 运行态与数据隔离

### 5.1 应用数据库

- 应用数据库路径由 `APP_DB_PATH` 明确配置，默认指向项目 `data/duck_diary.db`。
- 运行服务加载时记录 `db_mode=app`。
- 首次止血部署先停止旧服务，归档当前数据库和日志，再创建全新 schema 和干净演示数据。
- 当前数据不迁移；演示种子保持确定性，可重复生成。

### 5.2 测试数据库

- pytest 每个测试会话创建独立临时 SQLite 文件，并通过 fixture 注入数据库引擎。
- 删除 `tests/test_api.py` 和 `tests/e2e.py` 中导入应用引擎后直接 `drop_all()` 的做法。
- 测试启动时执行路径护栏：若数据库路径等于应用数据库，或位于正式 `data/` 目录，测试立即失败并拒绝执行。
- 默认测试不得调用真实 LLM 或真实 TTS；真实集成测试单独显式启用，仍使用临时数据库。
- 验收时记录应用数据库测试前后校验值，必须完全一致。

### 5.3 版本握手

- 新增单一版本文件，包含 `release_id`、`api_version` 和 `schema_version`。
- 后端进程在启动时读取并冻结版本值，通过 `GET /api/health` 返回：
  - `release_id`
  - `api_version`
  - `schema_version`
  - `db_mode`
  - `analysis_worker_status`
- 前端启动时读取磁盘当前版本文件和后端健康检查结果。
- `release_id`、`api_version` 或 `schema_version` 不一致，或 `db_mode` 不是 `app` 时，显示维护页并禁止业务操作。
- 该机制专门阻止“静态前端已更新、后端仍是旧进程”的混合运行态。

## 6. 教师 PIN 与本机边界

- 服务启动仅绑定 `127.0.0.1`，不再监听 `0.0.0.0`。
- 移除通配 CORS；前后端同源运行，不接受跨域业务请求。
- 第一次进入教师端时设置 4–6 位 PIN，服务端仅保存加盐哈希。
- PIN 验证成功后签发 HttpOnly、SameSite=Strict、无持久化过期时间的浏览器会话 Cookie。
- 关闭浏览器后 Cookie 失效；页面提供“立即锁定”，调用服务端注销并清除 Cookie。
- 教师数据读取、排班修改、审阅、停用和分析重试接口必须校验教师会话。
- 幼儿端仅开放今日值日名单、活动会话、聊天、会话完成和 TTS 所需的最小接口。
- 同一浏览器会话已解锁时，“老师帮忙”可直接进入；未解锁时显示 PIN 输入。

## 7. 幼儿端交互状态机

### 7.1 状态

幼儿端使用单一状态机，不再依靠分散布尔值组合：

1. `welcome`：欢迎页，等待用户手势解锁音频。
2. `loading_roster`：加载今日值日生。
3. `selecting_child`：选择今日值日生。
4. `opening`：播放开场语，可超时降级。
5. `ready`：等待点击或空格键开始。
6. `listening`：正在识别语音，显示实时或最终识别文本。
7. `submitting`：发言已暂存，正在提交；所有发送入口锁定。
8. `speaking`：服务端已确认发言并返回回复，正在播报。
9. `submission_failed`：发言未确认，保留文本并可重试或重新说。
10. `saving_conversation`：会话内容正在安全落库并创建分析任务。
11. `completed`：会话已保存，显示结束反馈；分析可以仍在后台运行。
12. `recovery`：刷新、中断或状态不一致时恢复活动会话或进入老师帮助。

任一时刻只允许一个状态。状态转换由明确事件驱动，并在自动化测试中逐条验证。

### 7.2 录音操作

- `ready` 状态下，点击主按钮或按空格键开始录音。
- `listening` 状态下，语音停顿触发自动结束；再次点击或再次按空格键可以提前结束。
- 主录音控件使用原生 `<button>`，支持 Enter 和 Space，并提供可见焦点。
- 动态提示通过 `aria-live` 播报；对话消息容器使用日志语义。
- 麦克风权限拒绝后立即显示“老师帮忙”和文字补录，不累计隐藏失败次数。
- 识别成功后将文本放入本地草稿，再进入 `submitting`；只有服务端确认后才从草稿移除。

### 7.3 今日值日生

- 正常情况下仅显示今日排班中的两名幼儿。
- 今日未排班时不回退显示全部幼儿，改为显示“今天还未排班，请老师帮忙”。
- 重复排班记录由后端唯一约束和幂等接口消除，前端仍按幼儿 ID 去重作为防御。

### 7.4 会话恢复

- 浏览器 `sessionStorage` 保存当前幼儿、会话 ID、阶段、待提交文本和 `request_id`，不保存 PIN。
- 页面加载时先查询服务端活动会话，再与本地状态合并。
- 服务端活动会话存在时恢复原对话；仅本地草稿存在时进入 `submission_failed` 并允许重试。
- 无法安全判断时进入 `recovery`，不得自动创建新会话。

## 8. 聊天、保存与分析任务

### 8.1 聊天幂等

- 每次幼儿发言生成 UUID `request_id`。
- `POST /api/chat` 必须携带 `request_id`。
- 数据库对 `request_id` 建唯一约束，并保存对应会话、消息和回复。
- 同一 `request_id` 重试时返回第一次的结果，不再次创建会话或调用 LLM。
- 请求进行中，录音按钮、空格键和文字补录统一禁用。

### 8.2 会话完成

- 用 `POST /api/conversations/{id}/complete` 取代前端将“分析完成”等同于“会话保存成功”的行为。
- `complete` 在单一事务内完成：
  1. 标记会话结束；
  2. 固化消息范围；
  3. 创建唯一分析任务；
  4. 返回 `conversation_saved=true` 和 `analysis_status=pending`。
- 幼儿端收到 `conversation_saved=true` 后可以显示“今天的话已经安全记下来啦”。
- 幼儿端不得声称流水或评估已经生成。

### 8.3 持久化分析任务

- 新增分析任务状态：`pending`、`processing`、`succeeded`、`failed`。
- 单机后台工作循环领取任务，执行提炼、情绪、心得和初评，并在同一业务事务内写入最终结果。
- 服务启动时重新领取遗留的 `pending` 任务，并把超过租约时间的 `processing` 任务恢复为可重试。
- 分析失败保存结构化错误摘要和重试次数；教师工作台显示失败状态及“重试分析”。
- 同一会话只能存在一个有效分析任务，重试不得生成重复评估或情绪记录。

## 9. 统一错误处理

### 9.1 API 客户端

- 前端所有请求统一经过一个 API 客户端，不再直接使用分散的 `fetch(...).then(r => r.json())`。
- 客户端检查 HTTP 状态、内容类型和标准错误结构。
- 标准错误结构固定为 `{"error":{"code":"...","message":"...","field_errors":{},"retryable":true,"request_id":"..."}}`；界面只依据该结构判断是否可重试，不解析任意后端字符串。
- 客户端提供超时、取消、请求序列号和幂等键支持。
- 页面离开或选择对象改变时取消旧请求；迟到响应不得覆盖当前界面。

### 9.2 错误呈现

- 每个异步操作必须具备加载、禁用、防重复、成功、失败和重试状态。
- 网络失败、HTTP 错误和业务校验失败使用不同文案，但都必须保留用户输入。
- 禁止用正常鸭鸭回复掩盖聊天失败。
- 禁止在未检查服务端成功状态时显示“已保存”“已确认”或“都记好啦”。
- 阻塞式 `alert()` 仅允许用于无法嵌入页面的浏览器级提示；业务反馈使用页面内状态或对话框。

### 9.3 TTS 降级

- 缓存命中目标为 500ms 内开始播放。
- 冷 TTS 超过 5 秒未开始播放即取消并降级到浏览器语音。
- 浏览器语音也失败时继续显示文字，并立即解锁后续操作。
- 任一 TTS Promise 都有超时和取消结算，暂停旧音频时必须释放旧等待状态。
- 无论 TTS 成败，开场、对话和结束状态机都必须继续推进。

## 10. 教师今日任务工作台

### 10.1 首页结构

首页按操作优先级排列：

1. 今日日期和当前解锁状态。
2. 今日值日生及排班状态。
3. “开始幼儿对话”主操作，以新标签页打开幼儿端。
4. 待审阅、分析中和分析失败队列。
5. 本周会话等辅助指标。

指标和成长趋势不再占据首屏主要空间。

### 10.2 导航与刷新

- 菜单点击必须更新 Hash，Hash 变化必须同步活动项和 `aria-current`。
- 浏览器前进、后退和刷新后保持正确模块。
- 进入今日工作台、审阅、成长和检索时重新获取关键数据。
- 创建、确认或重试成功后显式失效相关缓存。
- 不再使用“视图创建一次后永久缓存”的策略。

## 11. 教师双栏审阅工作台

### 11.1 布局

- 左栏：待审阅队列，显示幼儿姓名、会话时间、轮次和状态。
- 右栏顶部：重复显示幼儿身份、会话 ID 和时间，防止认错对象。
- 右栏上半部分双栏展示：左侧原始对话，右侧流水、情绪和心得。
- 右栏下半部分展示能力维度、分数和可编辑理由。
- 底部固定操作区显示脏状态、“保存草稿”和“保存并确认”。

### 11.2 原子保存

- 新增单一审阅提交接口 `PUT /api/conversations/{id}/review`，接收：
  - feeding logs
  - emotion
  - insight
  - assessment scores
  - assessment reasons
  - action：`save_draft` 或 `confirm`
- 服务端在单一事务内校验并保存全部字段。
- 任一字段失败时整体回滚，并返回字段级错误。
- `confirm` 仅在全部内容保存成功后改变评估状态。
- 前端仅在响应包含新的 revision 和完整保存结果时清除脏状态。
- 有未保存修改时，切换会话、导航或关闭页面必须提示。

### 11.3 安全操作

- 幼儿和小鸭的日常“删除”改为“离园/停用”。
- 确认对话框显示对象名称和影响范围。
- 成功后提供短时撤销入口。
- 物理删除不放在日常教师界面。
- 自动排班按日期和幼儿建立唯一约束；相同请求重复执行返回同一排班结果。

## 12. 可用性与无障碍

- 所有交互元素优先使用原生按钮、输入和标签。
- 所有输入具有持久可见 `<label>`，不只依赖 placeholder。
- 状态消息使用 `aria-live`；消息列表使用日志语义。
- 星级评分使用带维度名称和当前值的单选组或等效可访问控件，支持方向键。
- 焦点在视图切换、错误、弹窗和恢复后移动到明确位置。
- 核心触控目标不小于 44×44px。
- 普通文字对比目标不低于 4.5:1，UI 边界和焦点指示不低于 3:1。
- 支持 `prefers-reduced-motion`，关闭非必要弹跳、波形和庆祝动画。
- 止血验收分辨率为教师端 1024×768 及以上、幼儿投影端 1024×576 和 1280×720；本轮不承担手机端完整重构。

## 13. Lovable 脱敏原型

### 13.1 原型范围

Lovable 只制作以下两个高保真页面：

1. 教师今日任务工作台。
2. 左侧队列 + 双栏审阅工作台。

### 13.2 数据与安全边界

- 仅使用“小雨”“乐乐”等虚构姓名、虚构会话和固定 JSON。
- 不上传数据库、日志、环境变量、真实 API Key、真实幼儿信息或完整项目源码。
- 原型不连接本地后端，不执行真实保存或删除。
- 原型产物用于视觉层级、布局、文案和交互规范评审。

### 13.3 落地方式

- 48 小时止血版本继续使用现有无构建前端，优先实现可信交互。
- Lovable 原型确认后，按页面和组件分阶段移植样式及交互。
- React 全量迁移作为独立项目重新评估，不与止血版本捆绑。

## 14. 测试策略

### 14.1 后端与数据测试

- 数据库路径护栏测试。
- 聊天 `request_id` 幂等测试。
- 会话完成接口重复调用测试。
- 分析任务重试及服务重启恢复测试。
- 审阅原子提交、字段校验和事务回滚测试。
- 自动排班幂等及唯一约束测试。
- 教师会话鉴权、锁定及跨域拒绝测试。

### 14.2 浏览器交互测试

- 欢迎 → 今日值日生 → 点击录音 → 停顿发送 → 多轮对话 → 安全保存。
- 空格键开始和提前结束录音。
- 麦克风拒绝后立即进入老师帮助。
- 首次聊天超时、500、断网和重试，不得产生重复会话。
- 会话中刷新并恢复。
- 会话完成后分析中、分析失败和重试状态。
- 教师修改全部审阅字段，保存并重新获取后逐项一致。
- 有未保存内容时切换会话提示。
- 快速切换幼儿时旧响应不得覆盖当前内容。
- 删除改停用、确认影响范围和撤销。
- 仅键盘完成幼儿核心流程和教师审阅核心流程。

### 14.3 故障注入

- 对聊天、TTS、会话完成、分析和审阅接口分别注入延迟、500、非 JSON 响应和断网。
- 对所有主要按钮执行双击和快速重复键盘操作。
- 在 `submitting`、`speaking`、`saving_conversation` 和分析处理中刷新或重启服务。
- 测试结果必须包含交互断言和数据库断言，截图仅作为辅助证据。

## 15. 48 小时执行节奏

### 0–6 小时：运行态与数据止血

- 停止旧服务并归档旧运行态。
- 重建干净演示数据库。
- 隔离应用库和测试库，增加路径保护。
- 增加版本文件、健康检查和前端版本门禁。

### 6–18 小时：可信后端闭环

- 统一 API 错误结构。
- 实现聊天和排班幂等。
- 拆分会话保存与持久化分析任务。
- 实现审阅原子提交和教师会话校验。

### 18–30 小时：幼儿端状态机

- 实现点击/空格录音与自动停顿发送。
- 实现草稿、失败重试、TTS 降级和刷新恢复。
- 实现老师帮助和 PIN 会话。

### 30–40 小时：教师核心工作台

- 实现今日任务首页的最小可靠版本。
- 实现双栏审阅、脏状态和原子保存。
- 修复 Hash、活动导航和数据刷新。

### 40–48 小时：验收与交付证据

- 执行后端、浏览器和故障注入测试。
- 验证应用数据库校验值未被测试改变。
- 完成性能记录、可访问性检查和最终 GO/NO-GO 报告。
- 并行交付脱敏 Lovable 高保真原型，不接入真实后端。

## 16. 强制验收门槛

以下条件全部通过才允许判定 GO：

1. 完整运行测试后，应用数据库校验值不变。
2. 前端、后端和 schema 版本一致；不一致时业务页面不可操作。
3. 双击、超时、500、断网和重试均不产生重复会话、排班或评估。
4. 幼儿发言失败时原话保留，且界面不显示伪成功回复。
5. 刷新后可以恢复未完成会话或安全进入恢复流程。
6. 麦克风拒绝后立即显示老师帮助入口。
7. 会话保存成功后幼儿可结束；分析状态由教师工作台继续跟踪。
8. 教师修改的流水、情绪、心得、分数和理由重新获取后完全一致。
9. 审阅列表和详情明确显示幼儿姓名、时间、会话 ID 和状态。
10. 冷 TTS 超过 5 秒自动降级，任何语音故障都不阻断文字流程。
11. 自动排班重复执行保持同一结果。
12. 日常删除已替换为可撤销的停用或离园。
13. 核心幼儿流程和教师审阅流程可以仅用键盘完成。
14. 浏览器测试包含真实交互、故障路径和数据库断言。

任一门槛失败，结论保持 NO-GO，并记录失败证据与下一次复验条件。

## 17. 回滚策略

- 止血部署前保存当前代码提交、数据库副本和运行日志索引。
- 新数据库来自确定性 schema 和种子数据，可以随时重建。
- 每个执行阶段形成独立可回退提交，不把数据隔离、状态机和视觉优化混为一个不可拆分提交。
- 若版本门禁或核心 API 出现回归，恢复上一稳定提交并重建演示数据库。
- Lovable 原型始终独立，不参与运行版本回滚。
