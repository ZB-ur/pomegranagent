# 鸭鸭日记本 — 需求规格与设计文档

- 日期：2026-08-16
- 状态：待主人审查
- 场景：网站开发（Windows + Web）

---

## 1. 项目概述

「鸭鸭日记本」是一款面向幼儿园的个人教学辅助 Web 应用。幼儿园饲养多只小鸭，值日幼儿（每工作日 2 名，轮值）通过**语音对话**与 AI 角色「鸭鸭日记本」互动，记录饲养多只小鸭的过程。系统自动从对话中提炼结构化信息（饲养流水、情绪、心得），并对幼儿进行**隐性**的多维能力评估，教师端做数据沉淀与成长分析。

核心价值：用"和「鸭鸭日记本」聊天"这一幼儿友好的形式，把劳动教育过程自然沉淀为可回溯、可分析的数据。

## 2. 目标与成功标准

**目标用户**：单班级的教师（主要使用者）与值日幼儿（对话参与者）。

**成功标准**：
1. 幼儿能独立（或在教师轻辅助下）通过"按住说话"完成一轮与「鸭鸭日记本」的语音对话。
2. 每名值日幼儿的会话结束后，系统自动生成可审阅的饲养流水、情绪记录与能力评估（含评分理由）。
3. 教师能便捷地审阅、修正并确认 AI 提炼结果与评估。
4. 教师端能看到清晰的能力成长曲线，作为事后分析依据。
5. 幼儿全程对"评估/打分"无感知，仅体验"和「鸭鸭日记本」聊天 + 动画反馈"。

**范围约束**：无商业化，个人教学工具，单机部署（可连外网），单班级单园。

## 3. 用户与使用场景

| 端 | 使用者 | 设备 | 核心诉求 |
|---|---|---|---|
| 幼儿端 | 值日幼儿（每次 1 名进行对话） | 笔记本电脑 + 投影 | 语音对话、动画反馈、简单直观 |
| 教师端 | 班级教师 | 笔记本电脑 | 数据完整性、审阅修正、成长分析 |

**幼儿端要点**：界面为"投影给全班看 + 幼儿就近操作"兼顾，故采用大字号、大按钮、高对比度；丰富开场与过程动画（素材后续提供，当前占位）。

**规模参考**：单班级幼儿 20+ 人，每日 2 名值日约 10 个工作日轮转一圈。幼儿选择器、排班、名单等界面按 20+ 人规模设计（网格/搜索）；服务端数据量按"20+ 幼儿 × 长期使用"估算。

## 4. 已收敛的关键决策

| 议题 | 结论 |
|---|---|
| 部署规模 | 单班级、单园 |
| 幼儿规模 | 单班级 20+ 人（幼儿选择器、排班、名单等界面与数据量均需据此设计） |
| 部署形态 | 单机（Windows），可连外网，无商业化 |
| 后端 | Python FastAPI + 复用 DeepSeek 配置 |
| AI 架构 | 单体 + 直接 LLM 调用（不引入 CrewAI 多智能体） |
| AI 角色 | 「鸭鸭日记本」——一本会说话的日记本/陪伴助手，**非任何一只真实小鸭**；负责倾听、记录、提问引导、回答小鸭们的情况 |
| 前端 | React + Vite + Tailwind + Framer Motion |
| 数据库 | SQLite（本地存储、零运维） |
| TTS | Edge-TTS（免费、中文自然） |
| ASR | 可插拔抽象：MVP 用浏览器 Web Speech API，预留腾讯云/讯飞 |
| 会话边界 | 一次值日 2 名幼儿，每名幼儿的值日反馈 = 一轮完整会话 |
| 对话轮次 | 最大轮次可配置，默认 3 轮；一问一答（幼儿发言 + 日记本回复）算 1 轮 |
| 会话终止 | 达到最大轮次即结束；AI 判断信息已充分时可提前终止，并记录结束原因 |
| 评估机制 | AI 初评 + 教师确认；按次打分 + 周期汇总；幼儿无感知 |
| 能力维度 | 精简版 3 个（语言表达 / 同理心 / 勤劳启蒙）+ 可配置 + 评分理由(reason) |
| 提炼数据 | 可查看、可修正 |
| 小鸭知识 | 历史对话自动汇总成小鸭档案 + 教师可编辑 |
| 幼儿档案 | 全名 + 小名（选填）；对话时用小名称呼（无小名用全名） |
| 历史感知 | 对话注入「幼儿基础档案 + 近期对话摘要 + 小鸭档案」，动态调整内容营造"活人感"（不单独建长期画像） |
| 语音采集 | 按住说话（PTT） |
| 排班 | 周期开始教师手动录入 → 自动轮值 → 过程中可调整 |
| 分析重点 | 能力成长曲线 |
| 奖励记录 | 不涉及（原需求笔误，已删除） |
| 数据导出 | 不需要 |

## 5. 系统架构

```
前端 (React)
├── 幼儿端：语音对话、动画、PTT、投影友好
└── 教师端：班级/小鸭/排班管理、审阅修正、成长曲线、明细检索
        │  HTTP / WebSocket
后端 (FastAPI，单体)
├── 对话引擎：「鸭鸭日记本」角色扮演、多轮对话
├── 信息提炼：结构化 JSON 输出（流水/情绪/心得）
├── 能力评估：多维打分 + 评分理由
├── 小鸭档案：历史对话自动汇总 + 教师编辑
└── 语音抽象：ASR / TTS 可插拔接口
        │
├── 数据层：SQLite（SQLAlchemy ORM）
└── 外部服务：DeepSeek、ASR、TTS
```

关键原则：**语音、提炼、评估均通过可插拔接口/可配置项解耦**，能力维度做成配置字典，避免写死。

## 6. 技术栈

| 层 | 选型 |
|---|---|
| 前端 | React 18 + Vite + TypeScript + Tailwind CSS + Framer Motion |
| 后端 | FastAPI + Uvicorn + SQLAlchemy + SQLite |
| LLM | DeepSeek（`deepseek-v4-pro`，OpenAI 兼容接口，复用现有 `config/llm.py` 配置） |
| TTS | Edge-TTS（后端合成） |
| ASR | 抽象接口；MVP 浏览器 Web Speech API，预留腾讯云/讯飞 |
| 结构化输出 | LLM 返回 JSON（对话提炼 / 评估） |

## 7. 数据模型

核心实体（SQLite）：

| 实体 | 关键字段 | 说明 |
|---|---|---|
| `children` | id, name, nickname(nullable), avatar, active | 幼儿名单（全名 + 小名选填，对话用小名称呼） |
| `ducks` | id, name, avatar, status, note | 小鸭档案（含状态） |
| `duty_rosters` | id, cycle, date, child_id | 排班：某周期某日某幼儿值日 |
| `conversations` | id, child_id, date, started_at, ended_at, status, end_reason | 一轮完整会话（每名幼儿）；对话角色为统一的「鸭鸭日记本」虚拟形象，不绑定具体小鸭；end_reason 记录结束原因（达到轮次上限 / 信息充分提前结束 / 手动结束） |
| `messages` | id, conversation_id, role, text, audio_ref, created_at | 对话明细（原始文本） |
| `feeding_logs` | id, conversation_id, child_id, duck_id(nullable), category, content, occurred_at | 饲养流水（喂食/清洁/观察等），可关联具体小鸭 |
| `emotion_logs` | id, conversation_id, child_id, emotion, intensity, note, occurred_at | 情绪流水 |
| `insight_notes` | id, conversation_id, child_id, content | 心得/亮点（可选） |
| `assessment_dimensions` | id, key, name, enabled, weight, description | 可配置能力维度 |
| `assessments` | id, conversation_id, child_id, status(初评/已确认), overall | 一次会话的能力评估 |
| `assessment_scores` | id, assessment_id, dimension_id, score, reason | 每维度的分数与评分理由 |
| `duck_archives` | id, duck_id, summary, updated_at | 小鸭档案（AI 汇总 + 教师编辑） |

**可配置维度**：`assessment_dimensions` 表驱动，教师端可增删启停；默认三条：语言表达能力、同理心、勤劳启蒙。

**评分理由**：每条 `assessment_scores.reason` 必须引用对话中的关键语句作为依据，供教师复盘与后续调优评估模型。

## 8. 功能详述

### 8.1 幼儿端

1. **开场动画**：「鸭鸭日记本」形象 + 欢迎语（素材占位，动画规格预占）。
2. **按住说话（PTT）**：大按钮，按下采集语音、松开停止；录音中按钮态反馈（动画）。
3. **对话流**：语音播报（TTS）+ 文字气泡，投影友好大字体。
4. **小鸭情况问答**：幼儿询问小鸭当前/历史情况，AI 基于小鸭档案回答。
5. **结束动画**：会话结束的鼓励反馈（无任何评分暗示）。

### 8.2 教师端

1. **班级管理**：幼儿名单、小鸭档案（含 AI 汇总 + 编辑）。
2. **排班**：周期开始手动录入 → 自动轮值 → 可调整（含请假/补位）。
3. **值日记录审阅**：查看会话明细、修正提炼流水/情绪、确认评估（含各维度分数与理由）。
4. **能力成长曲线**：核心分析板块，按时间展示各维度变化趋势、幼儿间对比。
5. **明细检索**：按幼儿/日期/类型检索对话明细、流水、情绪记录。

### 8.3 AI 引擎（后端）

1. **对话引擎**：以「鸭鸭日记本」角色与幼儿多轮对话——一本会说话的日记本，负责倾听、记录、提问引导，并回答多只小鸭的情况（小鸭是真实的饲养对象，日记本不等于任何一只小鸭）；语气适合幼儿。
   - **上下文注入**：每轮对话注入「幼儿基础档案（全名/小名）+ 近期对话摘要 + 小鸭档案」，动态调整对话内容，营造"活人感"（如用小名亲切称呼、记得幼儿上次说过的事）。
   - **轮次控制**：最大轮次可配置（默认 3 轮，一问一答算 1 轮）；达到上限即进入收尾。
   - **提前终止**：AI 判断幼儿已表述出十分全面的信息时，即便未达最大轮次也提前收尾；结束原因写入会话记录，供教师了解。
2. **信息提炼**：会话结束后，从原始对话提炼结构化 JSON（饲养流水、情绪、心得）。
3. **能力评估**：基于整轮会话，对各维度打分并给出评分理由（JSON）。
4. **小鸭档案汇总**：定期/按需从历史对话汇总小鸭当前与历史情况。

## 9. 能力评估机制

- **触发**：每名幼儿一轮会话结束后自动触发初评。
- **打分**：AI 对每个启用维度输出 1–5 分 + 评分理由（引用对话原句）。
- **确认**：教师端审阅，可修正分数与理由，确认后入库生效。
- **汇总**：按周/月聚合为成长曲线（周期汇总）。
- **隐性**：幼儿端不展示任何分数；评分仅存在于教师端。

## 10. 语音交互方案

- **ASR（可插拔）**：接口 `ASRProvider.transcribe(audio) -> text`。
  - MVP：浏览器 Web Speech API（前端直采，零成本）。
  - 增强：腾讯云/讯飞 ASR（儿童中文识别更佳，有免费额度）。
- **TTS**：Edge-TTS（后端合成），接口 `TTSProvider.synthesize(text) -> audio`。
- **降级**：ASR 失败/空结果时，「鸭鸭日记本」可引导幼儿重说，或教师端可代为文字输入补充。

## 11. 关键流程

**值日对话流程**：
教师端选幼儿 → 进入幼儿端 → 开场动画 → 幼儿按住说话（PTT）→ ASR → 「鸭鸭日记本」LLM 回复（注入幼儿档案 + 近期摘要 + 小鸭档案）→ TTS 播报 →（循环，直至达到最大轮次或 AI 判断信息充分提前收尾）→ 会话结束 → 结束动画。

**会话后处理流程**：
会话结束 → 信息提炼（流水/情绪/心得）→ 能力评估（分数+理由）→ 教师端审阅 → 修正/确认 → 入库 → 成长曲线聚合。

## 12. 错误处理与边界情况

| 情况 | 处理 |
|---|---|
| ASR 识别失败/空 | 「鸭鸭日记本」引导重说；连续失败提示教师辅助（文字输入兜底） |
| 麦克风权限拒绝 | 前端引导开启权限，给出可视化提示 |
| LLM 超时/失败 | 重试一次；仍失败则提示稍后再试，会话数据保留 |
| TTS 失败 | 降级为纯文字气泡展示 |
| 会话被中断/未正常结束 | 已产生消息保留为草稿，教师可手动结束或补录 |
| 投影与笔记本分辨率差异 | 幼儿端用响应式 + 大字号，适配投影比例 |

## 13. 非功能需求

- **隐私**：数据本地存储（SQLite），不出园；无商业化。
- **易用性**：幼儿端零学习成本，教师端操作 ≤ 2 步完成日常审阅。
- **性能**：单机单班级，对话响应延迟目标 < 3s（不含 TTS 合成）。
- **可维护性**：能力维度、语音、模型参数均配置化，便于教师后期调整。

## 14. MVP 范围与后续迭代

**MVP（首版）**：
- 幼儿端：PTT 语音对话 + TTS 播报 + 基础动画占位 + 小鸭问答。
- 教师端：幼儿/小鸭/排班管理 + 会话审阅修正 + 能力成长曲线 + 明细检索。
- 后端：对话引擎 + 提炼 + 评估 + 小鸭档案 + 语音抽象（Web Speech ASR + Edge-TTS）。

**后续可迭代（非首版）**：更丰富动画素材接入、云端 ASR 增强、评估模型调优工具、多班级扩展。
